## What I learned
- PATH = the terminal's program-search list; Linux never checks the cwd (hence ./), Windows checks cwd first.
- venv = one environment per project, each with its own packages; create `python -m venv .venv`, activate `source .venv/Scripts/activate` (Git Bash).
- Verify, don't trust: `(.venv)` is a label that can lie; `which python` showing .venv in the path is the wiring.
- Two search lists: PATH finds programs (terminal); the module search path finds packages (import). pip installs into the active env's site-packages, never touches PATH.
- PATH resolves the COMMAND word; the cwd resolves the ARGUMENT — why `python myscript.py` still fails from elsewhere, and why batch-file deployment (section G) exists.
